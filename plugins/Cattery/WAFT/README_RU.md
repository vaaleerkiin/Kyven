# WAFT Cattery для Nuke

Нативная WAFT-a1 (5 итераций) в формате `.cat`. Проверено в NukeX 16.0v4.
При работе используются штатные Inference и VectorToMotion. Внешний Python,
PyTorch, сервер и компилятор для использования пакета не нужны.

Версия пакета 4: регулируемое подавление мелкой сетки в векторах, FP16
по умолчанию на GPU, экономное внимание SDPA и исправленный BBox после
VectorToMotion. Модель по-прежнему WAFT-a1;
разрешение и границы готовых векторов совпадают с входным источником.

## Установка

В полном пакете Kyven обе модели уже находятся в этой папке. Подключи Kyven
один раз через пользовательский `%USERPROFILE%/.nuke/init.py`:

```python
import nuke
nuke.pluginAddPath('D:/Kyven/hosts/nuke')
```

Замени путь на свой и перезапусти Nuke. Нода: **Kyven → WAFT SmartVector**,
либо Tab → WAFT. Для отдельной установки скопируй всю эту папку `WAFT` в
`.nuke/Cattery/`: файл должен оказаться по пути `.nuke/Cattery/WAFT/cat.json`.
Тогда нода доступна через **Cattery → Optical Flow → WAFT**.
Не оставляй две активные установки WAFT. Kyven Server и Model Manager не нужны.
Git checkout не содержит моделей: они входят в полный пакет либо пересобираются
по инструкции `development/waft/README_RU.md` в корне Kyven.

## Использование

Подключи последовательность кадров к единственному входу ноды.
Укажи **Input Colorspace** исходного изображения: внутри ноды кадры
переводятся в sRGB, как в исходном RAFT Cattery.

**Processing Resolution** задаёт максимальную длинную сторону кадра для
расчёта: **512 (Low VRAM)** по умолчанию, **768**, **1024** или **Full Source**.
Маленькие кадры не увеличиваются. Готовое поле векторов возвращается в
размеры входного источника; длины векторов масштабируются отдельно по X и Y.
Формат проекта не определяет разрешение выхода. BBox ограничен кадром входа.
Снижение рабочего разрешения экономит память, но может терять мелкие детали
и тонкие движения. Начни с 512; при достаточной свободной памяти попробуй 768.

**Precision**:

* **GPU FP16 (Fast)** — по умолчанию. Веса, свёртки и attention работают в
  FP16; накопление потока, координаты варпинга и выходные векторы — в FP32.
  Модель использует SDPA вместо явных полных матриц attention. Полноразмерное
  повышение разрешения выполняется только после последней итерации.
* **FP32 (Compatible)** — исходная модель для сравнения и работы на CPU.
  При снятии **Use GPU if available** автоматически выбирается FP32.

Это отдельные модели: `WAFT.cat` (FP16) и `WAFT_FP32.cat` (FP32).
При обычной работе загружается выбранная версия. Нативный переключатель
Inference `halfPrecision` отключён: пониженная точность уже встроена в модель.

**Grid Suppression** — от 0 до 1, по умолчанию 1. Перед масштабированием
выполняется bilateral-фильтрация каждой пары векторов независимо. Она уменьшает
мелкую пространственную рябь, ограничивая смешивание через перепады движения.
При 0 фильтр полностью отключается и возвращается сырой результат модели.
Это постобработка векторов; веса модели не изменялись. Очень мелкие реальные
движения тоже могут сглаживаться.

**Edge Threshold** — порог разницы векторов в пикселях рабочего разрешения,
по умолчанию 0.25. Уменьшение порога лучше сохраняет мелкие границы движения,
увеличение сильнее подавляет рябь. Исходный RGB не участвует в весах фильтра.

Проверено на кадре 77 из пользовательского клипа: в выбранной области стены
RMS высокочастотного остатка снизился примерно на 52%; IoU маски движения
с порогом 1 пиксель составил 0.999987. Это измерение одного кадра и одной
области, а не гарантия для всех материалов. Тестовое резкое изменение вектора
с 3 до 8 пикселей сохранилось с ошибкой менее 0.01 пикселя.

**Output Mode**:

* **Motion Vectors** — `forward.u`, `forward.v`, `backward.u`, `backward.v`.
  Выход преобразуется штатной нодой VectorToMotion для совместимости с
  потребителями motion-векторов Nuke, включая VectorBlur.
* **Smart Vectors** — `smartvector_f01_v01.n_u`, `.n_v`, `.p_u`, `.p_v`.
  Схема упаковки, соседние кадры и коррекция знаков взяты из предоставленного
  RAFT Cattery. Выход можно записать в EXR с channels=all для VectorDistort.

На выходе только выбранные векторные каналы, как у предоставленного RAFT.
Для сохранения RGB используй Copy/MergeCopy в исходную ветку.
На краях последовательности соседний кадр определяется настройками Read.
Рекомендуется использовать GPU и режим GPU FP16.

Проверка модели на RTX 4070 Laptop, вход 512×288: FP32 — 491 МиБ пиковых
выделений PyTorch, FP16 — 296 МиБ. Это память контрольного расчёта одной
пары кадров, а не общий расход VRAM приложения Nuke. В Nuke одновременно
нужны два направления потока, буферы изображения и память интерфейса.
Внутренний FP16 сохраняет финальные смещения в float32, но допускает небольшие
численные отличия от FP32.

## Установленная копия

В Kyven рабочий пакет расположен в `plugins/Cattery/WAFT/`. Внутри сохранены
`cat.json`, `WAFT.gizmo`, обвязка, иконки, лицензия и обе модели `.cat`.
После обновления перезапусти Nuke и создай новую ноду WAFT. Уже созданные
ноды в открытом скрипте сохраняют старый внутренний граф.

## Состав

* `WAFT.cat` — FP16-модель, созданная CatFileCreator в NukeX.
* `WAFT_FP32.cat` — модель полной точности для совместимости.
* `WAFT.gizmo` — граф по образцу предоставленного RAFT Cattery.
* `cattery_waft.py` — настройка модели и элементов интерфейса.
* `cat.json` — описание пакета Cattery.

Модель: https://github.com/princeton-vl/WAFT (ветка waftv2, архитектура a1).
Веса: рекомендованный авторами checkpoint из README репозитория,
Google Drive ID `1CxzBQx0iSg6AyIgt6MF0ROlF_cAeZLPC`.
Веса загружаются строго: все параметры должны совпадать с архитектурой.
Экспорт поддерживает разные размеры кадров; число итераций фиксировано: 5.

В Kyven код и инструменты повторной сборки находятся в `development/waft/`.
Инструкция восстановления — `development/waft/README_RU.md`, руководство ноды —
`docs/WAFT.md`. Для отдельного использования папка разработки не нужна.
Документация конвертации:
https://learn.foundry.com/nuke/developers/16.0/catfilecreationreferenceguide/simple-example.html
